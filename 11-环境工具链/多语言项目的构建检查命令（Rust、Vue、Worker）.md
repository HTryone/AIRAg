# 多语言项目的构建检查命令（Rust、Vue、Worker）

**结论**：接手一个仓库，先查它有哪几种语言，再逐层配检查闸门。**不存在一套命令打天下** —— 尤其要小心"纯 JS 项目根本没有类型检查这一层"。

谁需要看这条：接手多语言仓库、不知道改完该跑哪些检查的人。

---

## 一、各语言该跑什么

| 语言 / 层 | 检查命令 | 关键点 |
|---|---|---|
| **Rust** | `cargo fmt --check` → `cargo check` → `cargo clippy --all-targets -- -D warnings` → `cargo test` | 静态检查**只覆盖当前编译目标**，换个平台要重跑。详见 [Rust 与 Tauri 后端改动怎么验证](../03-桌面与移动端/Rust%20与%20Tauri%20后端改动怎么验证.md) |
| **前端 Vue / TS** | `npm run build`（必须包含类型检查） | 打包器会直接剥掉类型，不单独跑类型检查的话，类型错能过本地，在部署阶段才炸 |
| **Node 后端（TS）** | `tsc -p tsconfig.json` | — |
| **Node 后端（纯 JS）** | 干跑部署，例如 `npx wrangler deploy --dry-run` | **没有类型检查这一层** |

---

## 二、最容易踩的一条：纯 JS 项目没有类型检查

纯 JS 的 Worker / 脚本项目里：

- 没有类型检查，写错了只能靠跑
- **而且不能写类型注解** —— 写了会直接构建失败（报 `Unexpected '>'` 这类语法错）
- 需要标注类型时用 JSDoc 注释

**推论**：别对一个纯 JS 项目说"跑一下类型检查就行"，它没这一层。

---

## 三、产物也要验

跑完检查不算完，产物本身要验：

| 产物 | 怎么验 |
|---|---|
| 安卓包 | 签名验证（期望通过）；解开看 `lib/` 里只含目标架构 |
| 前端产物 | 看压缩产物（`.gz` / `.br`）生成了没 |

---

## 四、避坑表

| 坑 | 后果 | 正确做法 |
|---|---|---|
| 以为所有项目都能跑类型检查 | 纯 JS 项目里这条命令根本不存在 | 先查仓库有哪几种语言 |
| 只跑打包命令 | 类型错被打包器剥掉，部署阶段才炸 | 显式跑类型检查 |
| 静态检查只跑一个平台 | 其他平台的代码根本没被检查 | 分目标各跑一遍 |
| 在纯 JS 项目里写类型注解 | 构建直接失败 | 用 JSDoc |
| 检查全绿就交付 | 产物本身可能是坏的 | 查签名、查架构、查压缩产物 |
