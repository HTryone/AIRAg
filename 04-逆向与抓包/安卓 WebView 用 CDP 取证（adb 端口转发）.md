# 安卓 WebView 用 CDP 取证（adb 端口转发）

**结论**：正式包里前端的控制台日志看不见。用 adb 把调试端口转出来，浏览器打开调试页，就能直接在控制台里调接口复现问题。

谁需要看这条：调试安卓 App 内嵌网页的人。

---

## 一、为什么需要

| 包类型 | 前端日志 |
|---|---|
| 调试包 | 能看 |
| **正式包** | `console.*` 全不可见 |

正式包出问题时，logcat 里只有原生层的日志，前端在干什么完全不知道。

---

## 二、怎么做

### 第 1 步：查进程号

```bash
adb shell ps | grep <你的包名>
```

### 第 2 步：转发调试端口

```bash
adb forward tcp:9222 localabstract:webview_devtools_remote_<进程号>
```

### 第 3 步：浏览器连上

打开 `chrome://inspect`，就能看到对应的 WebView，点进去是完整的开发者工具。

### 第 4 步：控制台里直接调

在 Console 里直接调壳提供的命令（例如 `invoke('plugin:xxx', {...})`），复现问题。

**这是取证手段**：先在这里确认问题真的存在、复现条件是什么，再动手改代码。

---

## 三、三个要点

| 要点 | 说明 |
|---|---|
| **先取证再改** | 不要为没证实的猜想去改代码。在这复现出来了再动手 |
| 改设置要冷重启 | 改了某些设置后，要**清数据冷重启一次**才生效 |
| 坐标点击不准 | `adb shell input tap <x> <y>` 在 WebView 里坐标偏移严重，点不准按钮。Tab 键导航只在 WebView 拿到焦点时有效。**别靠点坐标做自动化** |

---

## 四、避坑表

| 坑 | 后果 | 正确做法 |
|---|---|---|
| 没取证就改代码 | 改的可能是猜错的方向 | 先在这里复现，确认了再改 |
| 用坐标点击做自动化 | 点不准，测试结论不可信 | 用控制台直接调接口 |
| 改了设置没冷重启 | 改动看起来没生效 | 清数据冷重启一次 |
| 用正式包调试却期望看到日志 | 什么也看不到 | 走端口转发 |
| 覆盖安装后验证 | 装的是旧壳 | 卸载重装 |
