# Electron 客户端逆向

从桌面客户端里挖出内部 API 和凭据，让脚本能直接调。这是完整流程，单独看这一篇就够。

**流程**：找到 asar → 提取字符串 → 定位凭据文件 → 试接口 → 判定能不能脚本化。

---

## 一、asar 包在哪、能不能读

Electron 应用的代码打包在 `resources/app.asar`（安装目录下）。

**asar 是打包不是加密**，里面的 JS 是明文，直接用 Python 读就行，不需要解包工具。

```python
p = r"C:\Users\xxx\AppData\Local\Programs\某应用\resources\app.asar"
d = open(p, "rb").read().decode("utf-8", "ignore")
```

---

## 二、提取字符串

**不要用 grep。** 压缩后的 JS 一行几万字符，grep 匹配到就直接输出：

```
[Omitted long matching line]
```

什么都看不到。用 Python 的 `find` + `repr()`：

```python
for kw in ["checkin", "Authorization", "getAuthSavePath"]:
    i = 0
    while True:
        i = d.find(kw, i)
        if i < 0:
            break
        print(kw, "->", repr(d[max(0, i-300):i+300]))
        i += 1
```

要点：
- `repr()` 把换行转义掉，输出仍是单行，不会被截
- 二进制读 + `errors="ignore"`，避免个别字节解码失败
- **关键词顺序**：先搜函数名（`getAuthSavePath`、`getBasePath`、`AuthenticationStorage`），再搜接口路径（`/v2/billing/`），最后搜协议字段（`Authorization`、`accessToken`）

函数名比接口路径更容易命中，因为路径常被拼接成片段。

---

## 三、定位凭据文件

在 asar 里搜这些关键词，读它附近的路径拼接逻辑：

```
getAuthSavePath
getBasePath
EXTENSION_DATA_DIR_NAME
sharedDataPath
AuthenticationStorage
```

然后按代码里的拼接顺序手动还原路径。

### 实例：WorkBuddy

```
getAuthSavePath()  →  path.join(sharedDataPath, "auth", `${authenticationId}.info`)
getBasePath()      →  <LOCALAPPDATA>/CodeBuddyExtension/Data/Public
```

拼出来：

```
%LOCALAPPDATA%\CodeBuddyExtension\Data\Public\auth\workbuddy-desktop.info
```

明文 JSON，字段：

| 字段 | 用途 |
|---|---|
| `auth.accessToken` | 接口鉴权 |
| `auth.refreshToken` | 续期（大概率用不了，见下） |
| `auth.domain` | 部分接口要放在 `X-Domain` 头 |
| `auth.expiresAt` | 到期时间戳，毫秒 |
| `auth.refreshExpiresAt` | 刷新令牌到期 |
| `account.uid` | 放 `X-User-Id` 头 |
| `account.nickname` | 日志显示用 |

### 三个注意点

1. **有些应用存在 `local_storage/*.info`，且是 gzip + base64 编码的**，要先解压再看
2. **拿到 refresh token 不等于能续期**。刷新需要 client_id 和 refresh endpoint，产品配置里经常不暴露。那就只能靠客户端重新登录来续期，脚本定期提醒用户重新导出
3. **多账号**：客户端切换登录通常用 `fs.renameSync` 覆盖同一路径，所以要给每个账号单独存一份快照文件。导出后随便切账号，已存的快照不受影响

---

## 四、试接口

拼好请求头发一次，**拿到 `code:0` 才算通**。

```python
headers = {
    "Accept": "application/json",
    "Content-Type": "application/json",
    "Authorization": "Bearer " + token,
    "X-User-Id": uid,
}
if domain:
    headers["X-Domain"] = domain
```

通用套路：
- 同时准备**多个端点**（主域名 + 备用域名），依次尝试取第一个成功的
- 超时 20 秒，太长会拖垮批处理
- 写操作（签到、领奖、下单）**先调查询接口确认状态再执行**，保证幂等

---

## 五、判定能不能脚本化

有些接口免签名，有些要签名 —— **同一服务里两种都有**。

### 实测案例

WorkBuddy 的积分查询接口 `/v2/billing/meter/get-user-resource`：

```
2 个端点 × 3 组请求头（含 X-Product / X-Client-Type）→ 全部 403，code 10085「请求不合法」
```

而同一服务的签到接口 `/v2/billing/meter/daily-checkin` 免签名，脚本正常调用。

### 止损线

试到这个程度就停：

1. 换端点（主域名 + 备用域名）
2. 换请求头组合，2-3 组，把从 asar 里找到的疑似自定义头都加上
3. 换 body 参数

还是 403 + "请求不合法" → **判定需要额外签名，放弃脚本化**，改为读客户端界面或让用户提供数据。

不要继续试第 4、5、6 组。这是盲目迭代，见 [改之前先拿证据](../07-排错方法论/改之前先拿证据.md)。

签名逻辑通常在客户端 JS 里（搜 `sign`、`hmac`、`signature`），但即使找到了，也往往依赖客户端内部状态（时间戳 + 随机数 + 设备指纹），脚本复现成本极高，一般不值得。

## 六、避坑

| 坑 | 后果 | 正确做法 |
|---|---|---|
| 用 grep 搜 asar | 输出被截成 `[Omitted long matching line]` | Python `find` + `repr()` |
| 一次读整个 asar 到内存再正则 | 大文件慢且难定位 | 按关键词 `find` 逐个看上下文 |
| 以为有 refresh token 就能续期 | 续期失败，脚本以为能长期跑 | 先确认 refresh endpoint 和 client_id 是否暴露 |
| 只存一份凭据 | 切换账号后凭据被覆盖 | 每个账号单独导出一份快照 |
| 接口 403 继续换参数试 | 浪费时间，拿不到新信息 | 按止损线判定，改走客户端界面 |
| 找到接口就直接定时跑 | 重复执行出问题 | 写操作先查状态，保证幂等 |
| 默认入口是 `app.asar` | 改了半天发现代码根本没加载 | 先 `ls resources/` 确认形态：有的 App 已解包，入口是 `launch.js` / `launch.dist.js` 而非 asar（运行时 Hook 见 `Electron 客户端运行时 Hook 与补丁`） |

## 七、打包 JS 还原：Wakaru 能拆包、能 ES6 化，但变量名救不回来

**结论**：压缩后的**变量名永久丢失**，任何工具都恢复不了。工具能做的是「拆包 + ES6 规范化」，让结构和逻辑可读；**名字只能读代码推断后手工重命名**。

**实测（2026-10-14，Parcel 打包的浏览器扩展）**：

| 事实 | 证据 |
|---|---|
| 模块 ID 是随机的 5 位串（如 `6SwVT`），但**源码路径与导出名完整保留** | 拆包后每个文件头都带得出「模块 ID（原版路径）」 |
| 无 source map，模块间靠 `require()` 串起来 | 拆出来的模块可以按 require 关系还原调用图 |
| 有的工具的源码恢复能力**在 Windows 上被硬编码拒绝**：要求 Linux x64 且需要 `/usr/bin/prlimit` | 源码里直接判 `process.platform === "linux"`，本机无 WSL/Docker 时怎么配都进不去 |
| 替代方案：直接驱动 Wakaru 本体（npm 包带 Windows 预编译二进制） | 能力等价、跨平台 |

**两层工作流（可复用）**：

1. **自动层**：用 Wakaru 跑一遍「拆包 + ES6 化」，结构清晰可搜。这一步是机器活，必做。
2. **语义层**：挑重点模块，按代码里**既有的证据**（导出名、require 路径、调用返回值）把 `e/t/r/n` 推断成有意义的名字，再补注释。**这一步没有工具能代劳**，靠读代码。

**改名之后必须证明「只改了名字」**：抹掉所有标识符名、把代码规范化，逐字节比对前后 —— 不一致就说明改的不只是名字。可读化 CSS/HTML 同理：去掉空白后逐字节一致才算等价。

## 八、字体反爬：页面显示的字和源码里的码位不是一回事

**结论**：一类教育/考试系统把正文里的关键字符换成**自定义字形编码**：DOM 里拿到的是「看起来对、复制出来是乱码」的私有字符，页面用一张**映射表**（大量「路径哈希 → 真实字符码位」条目）在运行时把码位换回去。

**怎么识别**：

- 直接 `innerText` 取出来的中文是方块/生僻字，但**截图看是正常的**；
- 页面加载的脚本里有一张**很大的映射表**（几万条 `{ "8位十六进制": 数字码位 }`）；
- 调用链里能搜到「取字形路径 → 哈希 → 用哈希当键查表 → `String.fromCharCode`」。

**照抄实现时最容易踩的两个坑（实测，两次返工）**：

| 坑 | 后果 | 正确做法 |
|---|---|---|
| 用 `/(\d+):(\d+)/` 这类正则去抓表里的键 | **把十六进制键截断**（`f51dc036` 被截成 `036`），265 处键损坏，查表全部查空 | 键**原样按字符串**保留，不要按数字处理 |
| 把键解析成数字 | 丢掉前导 0（`036` → `36`），与运行时算出来的字符串键对不上 | 键永远是**字符串**，值才是码位数字（注意可能写成科学计数法，如 `23e3` 表示 23000） |

**提取后必须逐条校验**：写一个校验脚本，解析原脚本里的表字面量和新生成的表文件，比对**条目数、每个键、每个值、顺序**是否完全一致，排除元数据字段（`author`/`namespace`/`license`/`version`）。不对齐就不算提取成功。

**验证链**：哈希取的是字形路径 JSON 序列化后的某一段（如 MD5 后取后 8 位）—— 一定要回到调用点确认「用的是字符串还是数字、切片取第几位」，不要凭表里的样子反推。

## 九、判定「能不能本地绕」：先分清遮罩和硬拒绝

**结论**：想判断一个会员/配额功能能不能靠改前端绕开，**先看阻挡发生在哪一层**。同一个产品里经常同时存在两套：**展示层遮罩**（前端自己盖住，改掉就没了）和**服务端硬拒绝**（前端只负责弹窗，改客户端一律无效）。

**实测（2026-10-14，某学习类浏览器扩展 v1.17.1）**：

| 现象 | 层级 | 证据 |
|---|---|---|
| 某个 AI 通道的响应里带一个「是否遮罩」标志，前端 watch 到就弹开通会员弹窗，而**题目数据本身照常下发** | **展示层遮罩** | 响应里数据完整，前端只是盖上弹窗 |
| 额度用尽返回业务错误码（如 `4002`），前端收到后停下任务 | **服务端硬拒绝** | 客户端全量扫描：**没有**剩余次数字段、没有计数器、没有额度判断 |

结论落在第二类：客户端只做「发请求 + 收到错误码后弹窗」，改本地的 `isVip` / `showVipMask` / 额度处理函数**一律无效**；把处理函数改成返回 true 只会让程序空转、反复被拒。

**判定流程**：

1. 找一个「正常额度」和「额度用尽」的对照，抓两次响应，比较**数据本体**是否一样。
2. 数据一样、只是多了个标志位 → 展示层遮罩。
3. 数据为空 + 业务错误码 → 服务端硬拒绝，**到此为止，别改客户端**。
4. 客户端有没有额度计数器：全局搜「次数 / 额度 / 剩余 / limit / remaining」的中英文关键词，一个都没有就是服务端判定。

**顺带**：错误码表要从客户端源码里**挖出来**（登录失效、额度用尽、OCR 失败等各有编号），排查时比文案可靠。

## 十、构建脚本里加一道「还原版仍可加载」检查

**结论**：把压缩代码还原成可读版之后，**光看代码能读不算数**，必须证明它还原封不动是一个能被加载的扩展：文件清单、manifest 引用、JS 语法三项逐项过闸。

**实测（2026-10-14）**：

| 检查 | 内容 | 结果 |
|---|---|---|
| 与官方原包逐文件 SHA-256 比对 | 结论分四类：字节一致 / 内容不同 / 官方有而可读版缺 / 可读版多出 | 运行文件与官方**逐字节一致**，多出来的只有源码目录 |
| `manifest.json` 引用的每个文件是否存在 | 少一个文件，浏览器加载即报错，而 JS 语法错看不出来 | 全部存在 |
| 所有 JS 过一遍语法解析 | 拆分/改写时最容易留下的就是语法错 | 全部通过 |

**做法**：

1. 写一个**不依赖浏览器**的校验脚本：遍历目录 → 解析 `manifest.json` 的所有引用（后台脚本、内容脚本的 js/css、web 可访问资源、弹出页/设置页）→ 逐个确认存在 → 所有 `.js` 用解析器（如 acorn）过一遍 → **有失败项就退非零退出码**。
2. 与官方原包做**逐文件哈希比对**，差异分类输出（不是只报「共 N 个不同」）。
3. 把这两步接进构建脚本，和类型检查一起当闸门。

**反例**：改完直接加载，看到图标出来就当成功 —— 后台脚本语法错、某个资源路径写错，往往要用户点开某个页面才炸。

> ⚠️ 区分两种「还原后能不能用」：**语法/结构可加载**用上面的静态校验就够；**运行时行为是否与原版一致**只能靠实测，别拿静态校验冒充行为验证。
