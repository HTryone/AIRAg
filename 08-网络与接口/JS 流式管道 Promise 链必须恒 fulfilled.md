# JS 流式管道 Promise 链必须恒 fulfilled

**结论**：链式管道里写成 `.then(下一步).catch(再抛出)`，一旦失败，整条链会永久停在失败态，之后每个请求都秒失败——而且报的还是第一次那个错。

正确写法是 `.then(任务, 任务)`，让异常在任务内部自己吞掉，链始终处于成功态。

谁需要看这条：写 JS/TS 流式上传、下载、管道处理的人。

---

## 为什么

典型写法（错的）：

```js
writeChain = writeChain.then(pump).catch((e) => { throw e })
```

分析：

1. `pump` 里某个请求失败 → 抛异常
2. `catch` 捕获后又 `throw` → **这个 promise 变成 rejected**
3. `writeChain` 现在是一个 rejected 的 promise
4. 之后每次 `writeChain.then(...)`，then 的回调**根本不执行**，直接走 rejected 分支

结果：第一次失败之后，后面所有请求都是秒失败，且错误信息永远是第一次那个，看起来像是"整条管道坏了"，实际只是链的状态没复位。

---

## 怎么做

让链恒处于成功态，异常在任务内部处理：

```js
function task() {
  return doWork().catch((e) => {
    // 异常在这里处理掉，不往外抛
    reportError(e)
  })
}

writeChain = writeChain.then(task, task)
```

关键点：

| 要点 | 说明 |
|---|---|
| 用 `then(成功回调, 失败回调)` 两参数形式 | 不管链当前什么状态，都继续往下走 |
| 异常在任务内部吞掉 | 不让异常逃逸到链上 |
| 错误另走上报通道 | 该报的错照样报，只是不通过链的状态传递 |

---

## 避坑表

| 坑 | 后果 | 正确做法 |
|---|---|---|
| `.catch(e => { throw e })` | 链永久 rejected，后续全秒失败 | `then(任务, 任务)` |
| 只看第一个报错 | 以为是同一个问题反复出现，其实后续根本没执行 | 怀疑链状态时，打点确认任务有没有真跑 |
| 用链的状态表示业务成败 | 一次失败污染整条链 | 业务成败用单独的标志位，不用 promise 状态 |
