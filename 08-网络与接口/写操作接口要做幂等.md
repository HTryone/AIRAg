# 写操作接口要做幂等

**结论**：领奖、签到、下单这类"写"接口，先调查询接口确认状态，再决定是否执行。让脚本可以安全地重复运行。

## 为什么

定时任务、失败重试、手动补跑都会导致同一天多次执行。不做幂等就会重复操作。

## 怎么做

```
1. 调查询接口，看 today_checked_in / 状态字段
2. 已经做过 → 记日志并跳过
3. 没做过 → 调写接口
4. 写完之后的处理也要能容忍重入
```

日志里写清楚是"已跳过"还是"刚执行"，排查时一眼能分辨。

## 附带

即使接口本身幂等，脚本也建议先查一次 —— 查询结果里的连续天数、累计积分这些信息，只有查询接口会返回。
