# Cloudflare 落点与跨境链路定位（CF-RAY、traceroute）

**结论**：浏览器直连对象存储传文件慢，十有八九是落点跨洲 + 跨境回程整形，**不是应用代码问题**。先拿出落点证据再谈优化。

谁需要看这条：排查跨境上传下载慢的人。有自建后端中转的可以跳过（你的数据面不一样）。

---

## 一、先分清两个面

| 面 | 干什么 | 例子 |
|---|---|---|
| **数据面** | 实际传字节 | 对象存储桶域名（通常是预签名直连） |
| **控制面** | 拿清单、拿签名、协商 | 后端服务域名（如 workers.dev） |

**两个面的落点可能完全不同。** 控制面很快不能说明数据面也快。

排查前先读代码确认：数据面到底是直连对象存储，还是走了自己的后端中转。**这个判断错了，后面全白做。**

---

## 二、五步查法

### 第 1 步：查域名解析

```bash
nslookup <你的数据面域名>
```

确认解析到哪个 IP 段。

### 第 2 步：取落点标识（最关键）

```bash
curl -sI --noproxy '*' --max-time 15 https://<你的数据面域名>/ | grep -i cf-ray
```

响应头里带的数据中心编号就是落点（例如 `XXX-SEA` 表示西雅图）。

**`--noproxy '*'` 是必须的。** 不加的话，你测的是代理节点的落点，结论全错 —— 这是这条排查里最容易犯的错。

### 第 3 步：看路由跳点

```bash
traceroute <你的数据面域名>
```

延迟从约 20 毫秒**暴涨到 180~220 毫秒的那一跳**，就是跨境出口。

### 第 4 步：判读是哪条腿被限

路径对称时（上传和下载走同一个域名、同一个落点）：

- **"下载比上传慢"** → 说明同一个远端节点上，出站那条腿被限得更狠，**不是下载走了更差的路由**
- **"并发调大无效"** → 多路连接共享同一个按 IP 限的出站池子，加大只是在池子里多分一点

### 第 5 步：下结论

拿到落点编号 + 路由跳点，才能说"这是网络问题"。**没有这两个证据就不要下结论。**

## 三、四条反模式

这几条比正着写更有价值：

| 反模式 | 为什么错 |
|---|---|
| 让用户手填预签名直链做探针页面 | 用户拿不到那个链接，做出来也没法用 |
| 凭"按 IP 限速"这种模糊说法下结论 | 没有落点编号 + 跳点当证据的说法一律不算数 |
| 把"下载慢"直接判成"绕了代理" | 先读代码确认数据面是不是直连，别猜 |
| 建议"断点续传跨刷新" | 纯浏览器没有后端检查点，结构上做不到。见 [纯前端无后端架构](../12-技术栈架构/纯前端无后端架构（加密、落盘、校验都在浏览器）.md) |

---

## 四、避坑表

| 坑 | 后果 | 正确做法 |
|---|---|---|
| 测落点不加不走代理的参数 | 测的是代理节点，结论全错 | `--noproxy '*'` |
| 只看控制面速度 | 数据面慢被漏掉 | 两个面分别测 |
| 没证据就说是网络问题 | 可能真是代码问题，被掩盖 | 落点编号 + 跳点，两个都要有 |
| 认定是网络问题后还继续调应用参数 | 白费功夫 | 确认是链路问题就改架构（加中转、换区域），不调参数 |
| 用峰值速度下结论 | 峰值好看不代表体验 | 看均值和波动 |
