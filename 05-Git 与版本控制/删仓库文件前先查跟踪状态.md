# 删仓库文件前先查跟踪状态

**结论**：删除 git 仓库内的文件前，先用 `git ls-files` 确认是否被跟踪，并且 `ls` 要在正确目录跑，不要用 `2>/dev/null` 吞掉报错。

## 为什么

被 git 跟踪的文件不能直接 `rm`，否则留下未暂存的删除，得在 commit 里额外解释。

更严重的坑：`ls` 跑错目录 → 报错 → 用 `2>/dev/null` 把报错吞掉 → 误判成"空目录" → `rm -rf` 删掉被跟踪的文件。曾经这样误删过上游 issue 模板。

## 怎么做

```bash
git ls-files <路径>      # 有输出 = 被跟踪
git status               # 看当前改动状态
ls -la <绝对路径>         # 确认路径真实存在且内容对
```

确认无误再删。

## 安全的

项目根目录的缓存 / 日志目录（`__pycache__`、`.wrangler`、`.playwright-cli`、`_log` 等）不在 git 里，可以放心删。
