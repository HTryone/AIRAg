# push 必须用户明确授权

**结论**：默认只 commit 不 push。用户明确说"push"或"推送"才执行，且 push 前必须 `git add -A` 暂存全部文件。

## 为什么

推送到远程是外部可见动作，撤回代价高。用户要求这条边界严格执行。

## 关键边界（高频踩坑）

「并入 main」「合并到主分支」「合入主分支」这些指令**只授权本地合并**，**绝不等于**授权 `git push origin main`。

推送远程必须用户**单独、明确**说"推送 main"或"推送远程"。

## 怎么做

```bash
git add -A          # 全量暂存，包括自动生成的文件
git commit -m "中文描述"
# 停在这里，等用户说 push
```

用户授权后：

```bash
git push
```

## 例外

用户明确说过"以后自动 push"的项目（如点对点传输项目），提交后可直接推。这个授权是**按项目**给的，不能外推到其他仓库。
