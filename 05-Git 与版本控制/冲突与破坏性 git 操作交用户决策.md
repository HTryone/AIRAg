# 冲突与破坏性 git 操作交用户决策

**结论**：git 冲突、强推、覆盖/删除标签、`reset --hard` 这类不可逆或有分歧的操作，停下来把选项摆给用户拍板；无冲突的常规操作（fetch、commit、打新标签等）直接做完。

## 为什么

2026-09-07 用户定的规矩，原话："冲突的时候，我来决策。" 冲突双方各有道理，AI 替用户选边容易丢改动；破坏性操作不可逆，选错无法挽回。

push 授权是另一条边界，见 [push 必须用户明确授权](push%20必须用户明确授权.md)。

## 怎么做

给用户的决策呈现格式：

1. 冲突/操作是什么（哪个文件、哪个分支）
2. 每个选项的后果（保留谁、丢什么）
3. 推荐哪项及理由

摆完等答复，不先斩后奏。

## 反例

merge 冲突时自作主张选了"保留自己这边"继续提交；本地分叉时直接 `reset --hard` 扔掉了用户改过的提交。
