# 文档必须对读者可用

写文档的唯一标准：**用户复制过去就能用，照着做就能成。**

三条具体要求，对应三个真实事故。

---

## 一、精简删的是废话，不是实操

用户说"精简"，指的是删掉啰嗦解释、重复内容、多余的变量引入；**不是**删掉实操步骤、附录、配置表。

### 事故

2026-08-29 把一份 408 行的文档精简到 80 行，顺手把用户要的附录 A（手动新建任务向导）、附录 B（一键重建命令）、附录 C（AI 提示词）、配置表全删了。用户原话："让你删的，你不删，不让你删的，全删了。"

### 该删的 vs 不该删的

| 该删 | 不该删 |
|---|---|
| 同一件事用三种方式各写一遍 | 从零开始的操作步骤（换电脑要用） |
| 变量定义、省事的"优化"写法 | 附录（给 AI 的提示词、一键命令） |
| 大段解释性废话 | 配置参数表（排查时对照用） |
| 已经失效的命令 | 命令的完整参数说明 |

删之前先把内容分成两堆，**拿不准的留着或问用户**，不要凭"感觉啰嗦"就删。

---

## 二、写进去的文件名必须核对存在

文档里提到的每一个文件名、命令、路径，写完后都要 `ls` 核对，不能凭记忆写。

### 事故

文档里写了 `run-status.bat` 和 `run-dry-run.bat`，但这两个文件根本不存在（目录里只有 `run-checkin.bat` 和 `export-current.bat`）。用户双击必然失败，还以为是命令写错了，反复排查了很久。

### 怎么做

```bash
ls -la <目录>
```

逐个对照。顺带能发现命名不一致（文档说 A，实际叫 B）。

同理适用于：命令有没有这个参数、配置项叫不叫这个名字、快捷方式指向的目标存不存在 —— 都要实际跑一次或读一次代码确认。

---

## 三、命令要能直接复制粘贴

文档里的命令必须是完整、可直接复制执行的一段，不能要求读者自己拼、自己替换、自己做前置准备。

### 为什么

用户的使用方式是「复制 → 粘贴 → 回车」。任何需要脑补的部分都会变成报错。

### 怎么做

- 前置的 `cd` 一起给出来
- 路径写全，不用 `<占位符>` 让用户自己填
- 不引用文档前面定义过的变量（见 [禁止在文档里引入 shell 变量](../02-命令行与脚本/禁止在文档里引入%20shell%20变量.md)）
- 每条命令给一句注释说明作用

```bash
cd /d/perca/zidqdworkbuddy/wb-checkin   # 先进入目录
python checkin.py --status              # 查账号状态
```

### 反例

```bash
python checkin.py $ARGS    # 自己替换 ARGS
见上文定义的命令          # 读者要往前翻
python /d/xxx/yyy.py       # 传给 Windows 程序会解析成 d:\d\xxx\yyy.py
```

## 四、写完自检

- [ ] 提到的每个文件都 `ls` 核对过存在
- [ ] 每条命令都能整段复制直接跑，没有占位符和变量
- [ ] 前置步骤（`cd`、依赖安装）都写全了
- [ ] 想删的内容过了一遍"该删 vs 不该删"表
- [ ] 同一件事没有用两种方式重复写
- [ ] 单独打开这个文档，不看别的，能不能照着做完
