# AIRAg 通用知识库

面向 AI 协作的经验库。按**领域 / 工具**分类，不按项目分类。

三个用途：
1. **防止犯错** — 已经踩过的坑，不再踩第二次
2. **新思路** — 可复用的解法与工具用法
3. **提高效率** — 拿到就能用，不用重新摸索

---

## 接手时怎么读

1. 先读 `01-AI 协作/` 全部条目 — 硬性约束，违反会直接惹恼用户
2. 再读 `INDEX.md` 找相关条目
3. 动手前扫一眼对应领域目录
4. 要往库里加东西，先读完下面三节规则（分类 / 拆分 / 写法）

不确定有没有相关条目时查 `INDEX.md`，**不要凭记忆判断**。

---

## 一、怎么分类：新经验放哪个目录

按**这条经验解决的是什么性质的问题**分，不是按涉及的技术分。

| 如果这条经验是…… | 放 |
|---|---|
| AI 该怎么做事 / 不该做什么，跟技术无关 | `01-AI 协作` |
| 命令行、脚本、bat、Python 怎么写怎么调 | `02-命令行与脚本` |
| Windows 系统功能怎么用（任务计划、环境变量、编码、开机自启） | `03-Windows 系统` |
| 从别人的程序里挖东西（逆向、抓包、找凭据、探接口） | `04-逆向与抓包` |
| git 操作和它的授权边界 | `05-Git 与版本控制` |
| 文档 / 说明怎么写给人和 AI 看 | `06-文档与表达` |
| 排查问题的思路、流程、止损线 | `07-排错方法论` |
| HTTP / API 调用、容错、幂等、重试 | `08-网络与接口` |
| Linux 服务器、远程主机（SSH、证书、端口、内存、邮件） | `09-服务器运维` |
| 凭据 / 密钥 / token 怎么存、怎么不进 git、漏了怎么办 | `10-凭据与安全` |
| 运行时环境本身（多版本、装包位置、PATH、隔离） | `11-环境工具链` |

### 归属冲突时

按这个顺序取第一个命中的：

1. 涉及 AI 行为准则 → `01-AI 协作`
2. 涉及凭据 / 密钥 / token 的存放与泄露处置 → `10-凭据与安全`（优先于所有技术目录）
3. 涉及运行时装哪个版本、装到哪 → `11-环境工具链`（优先于 `02-命令行与脚本`）
4. 涉及 Windows 专有功能 → `03-Windows 系统`（优先于 `02-命令行与脚本`）
5. 涉及 Linux 服务器 / 远程主机 → `09-服务器运维`（优先于 `02-命令行与脚本`）
6. 涉及某个具体工具的完整用法 → 该工具所属目录
7. 剩下按上表

`03` 和 `09` 的分界：**本地 Windows 机器**归 `03`，**远程 Linux 主机**归 `09`。两边都有的操作（比如都是命令行）按机器归属分，不要混。

`02` 和 `11` 的分界：**脚本怎么写**归 `02`，**脚本用什么跑、包装在哪**归 `11`。举例：bat 里中文会乱码 → `02`；装包装到了系统环境而不是项目 → `11`。

`10` 只管凭据本身（存哪、怎么拦、漏了怎么办）。服务器上的 SSH 配置、证书申请这些操作流程仍归 `09`。

### 拿不准 / 没有合适目录

- 放进最接近的目录，在 INDEX 里那行加个备注
- **不要擅自新建目录** — 新建目录属于结构调整，要先问用户

## 二、怎么拆分：不多拆，也不少拆

### 三步判定

**第一步：这个主题有没有流程？**（必须先做 A 再做 B 才能成，缺一步就不完整）

- 有 → **一个模块文档**，按流程顺序排章节
  - 例：Electron 逆向 = 提取 → 找凭据 → 试接口 → 判定能否脚本化，拆成四片每片都不完整
- 没有 → 进第二步

**第二步：是不是同一个工具 / 同一个功能的多个方面？**（新建、管理、排查、避坑都指向它）

- 是 → **一个模块文档**，按使用顺序排章节
  - 例：Windows 定时任务，曾拆成 5 片被用户批评"谁看得懂"
- 不是 → 进第三步

**第三步：几句话能不能说完？**（一个结论 + 一个做法 + 一个例子，一屏之内）

- 能 → **一个文件一条**
- 不能 → 拆成多条，**每条一个独立结论**

### 兜底标准

> **单独打开这一个文件，能不能看懂并照着做。**

能 → 粒度合适。不能 → 合。

### 拆多了的信号

- 文件名读起来像步骤名：`怎么建任务.md`、`怎么改时间.md`、`怎么查配置.md`
- 打开一篇，发现必须去看另一篇才知道在说什么
- 同一件事在两三篇里各讲一遍

### 拆少了的信号

- 一篇里塞了好几个互不相关的结论
- 标题只能叫「XX 规范」「XX 笔记」「XX 汇总」这种笼统词
- 想找其中一条，得通读全篇

### 条目数软约束

- 一个目录 **1 条** → 内容太少，考虑是不是该并进别的目录
- 一个目录 **超过 8 条** → 可能有能合并的，或者里面藏着一个该独立成篇的子主题

## 三、两种文档的写法

### 单条经验（一个文件一条）

文件名 = **结论本身**，中文，一眼看懂在说什么。

```md
# 标题（结论式）

**结论**：一句话说清该怎么做。

## 为什么
证据 / 原理 / 事故经过。写具体，写日期。

## 怎么做
可复制的命令或操作步骤。

## 反例
错在哪（可选）。
```

好名字：`禁止在文档里引入 shell 变量.md`、`回退用 reset --hard 不用 revert.md`
坏名字：`notes.md`、`踩坑记录2.md`、`关于变量的一些事.md`

### 模块文档（一个工具 / 一条流程一篇）

文件名 = **工具名或流程名**，名词，不带动词。

内部按**使用顺序**排章节：

```
这是什么 → 在哪 → 从零怎么做 → 一键怎么做 → 日常管理 → 排查 → 避坑表
```

不是每个模块都要有全部章节，但顺序照这个来。

好名字：`Windows 定时任务.md`、`Electron 客户端逆向.md`
坏名字：`定时任务相关.md`、`逆向笔记汇总.md`

## 四、扩展流程

1. **先查 INDEX** — 有没有相关条目？
   - 有 → **扩充那一篇**，不要新建（尤其是模块文档，加章节就行）
   - 没有 → 新建
2. 按第一节判定目录，按第二节判定粒度
3. 按第三节选模板写
4. **更新 `INDEX.md`** — 不更新等于没写，后面接手的 AI 找不到
5. 校验链接：新建 / 删除 / 改名后，跑一遍检查 INDEX 和正文交叉引用有没有断链

### 结构调整要授权

删除、合并、拆分、移动文件，以及新建目录，都**必须先给用户方案、拿到同意再动**。

方案里要写清：动哪几个文件、动完是什么样、为什么更好。**逐个列出将被删除的文件名。**

见 `01-AI 协作/撤销改动必须用户授权.md`。

## 五、写作要求

- **只写有证据的结论**。禁止"可能 / 怀疑 / 大概率 / 应该是 / 待验证"。
  有证据就陈述并附上（日志、实测输出、代码路径）；没证据就写"没有证据，无法确认 X"。
- 每条都要给出**能直接复制执行**的命令或步骤，不写空泛原则。
- 事故经过写清**日期和原话**，不要只写"曾经出过问题"。
- 只放跨项目通用的东西。单个项目的专有业务逻辑放项目自己的 memory。
- **不写死某一台机器**。用户名、盘符、绝对路径、账号、端口都不能照抄具体机器的值。见下面「怎么写通用的命令」。

### 怎么写通用的命令

约束目的：库是通用的，任何人、任何机器上复制命令都能跑，不要被你的具体环境锁死。

写命令分两层：

| 层 | 要求 | 例子 |
|---|---|---|
| 命令结构 | 完整可复制，可以含路径，但不带占位符 | `python -m venv .venv` |
| 实例特定的值 | 不写死，给「怎么查出你自己的」或尖括号占位 | `where python` / `<你的域名>` |

**能通用的就写通用的**。任何换台机器、换账号、过段时间就会变的值都别写死，下面这些值都要写成通用的（举例）：

| 具体的值 | 反面：写死的样子 | 通用的写法 |
|---|---|---|
| 用户名、家目录 | 直接写自己机器上的用户名 / 家目录 | `<你的用户名>` |
| 盘符、项目路径 | 直接写 `C:\...` 这类绝对路径 | `<你的项目路径>` |
| 公网 IP、内网 IP | 直接写具体 IP | `<你的服务器 IP>` |
| 域名、端口 | 直接写具体域名 / 端口 | `<你的域名>` / `<你的端口>` |
| 密码、API Token | 直接写凭据原文 | `<你的密码>` |
| 容器 ID、服务名、PID | 直接写 hash ID / 数字 PID | 写名字（容器标签、服务名） |

**写法二选一：**

- 优先：写尖括号占位（`<你的域名>`）+ 给「怎么查出你自己的」命令
- 实在要给完整示例：明说「下面是示例路径，替换成你自己的」

边界：

- 环境变量写名字（`%USERPROFILE%`、`$HOME`）不写展开值——对方机器同样有这变量
- 真要保留某个具体值（如 acme.sh 要求的 DNS 密钥名、Tauri keystore 占位符），加一句「这是工具硬性要求的传参名，不是可以省的」
- 验证别用 `echo $VAR`（PowerShell 不展开），用 `[Environment]::GetEnvironmentVariable("X", "User")`

```bash
where python                                       # 先查你机器上 python 的实际位置
"%USERPROFILE%\AppData\Local\Programs\Python\Python313\python.exe" -m venv .venv
```

和 [文档必须对读者可用](06-文档与表达/文档必须对读者可用.md) 不冲突：那条管**命令本身**写不写全，这条管**命令里出现的实例特定值**怎么写。
