# 怎么给 AI 派活

**结论**：派一个非琐碎的活，必须同时说清四件事 —— **目标、边界、验收标准、禁止**。缺一件，AI 就会自己脑补，脑补的部分八成不是你要的。

---

## 一、四要素写全

```
目标：把 X 从 A 提到 B
边界：只改 <哪些文件/模块>，其他一律不动
验收：怎么算做成了（可观测的结果）
禁止：明确列出不许做的事
```

| 项 | 说清什么 | 反例（太含糊） |
|---|---|---|
| 目标 | 量化，能测 | "优化一下速度" |
| 边界 | 具体到文件 / 模块 | "改改相关的地方" |
| 验收 | 跑一次能看到的結果 | "好用就行" |
| 禁止 | 不许重构、不许顺手修别的、不许动数据 | 不写 |

**完整例子**：

```
目标：把上传平均速度从 3 MB/s 提到 6 MB/s
边界：只改 src/transfer/ 下的分片与并发逻辑，不动加密和界面
验收：连续跑 3 次，平均速度稳定在 6 MB/s 以上，且断点续传仍正常
禁止：不要重构目录结构，不要顺手修别的 bug，不要改线上配置
```

改动可逆、一眼能看明白的琐碎任务可以直接说（如「把版本号改成 1.2.3」）。判断标准：**AI 有可能做多或做偏的，就要说清边界**。见 [授权与改动边界](授权与改动边界.md)。

## 二、任务书：一条活写一份文件，正文不进对话

**结论**：派活时**把任务书写成文件**，对话里只给路径，让子代理自己去读。任务书正文塞进对话，既撑大上下文、又抄不全。

- 全部任务书写在**同一个固定目录**，命名 `YYYY-MM-DD-<简称>.md`，任何窗口、任何会话都按同一流程找得到。
- 派活时传两个参数：**工作目录**（目标工作区根）+ **任务书路径**；选哪个子代理也由口令决定（说「下发 opencode」才走 OpenCode，没说就用自带的子代理）。
- **开工规程由工具统一注入**：工作区根、记忆文件路径、任务书路径，以及四步走 —— 读任务书 → 读工作区记忆 → 找现成工具 → 才动手。任务书里不用重复写这些。
- 任务书**只指路、不搬运**：工具、凭据、机器清单一律写「读工作区记忆，用里面的现成工具」，不要把命令、路径、账号一页页抄进去。

**为什么（用户原话级）**：「直接让他看对应工作区使用什么工具就行了。没必要你给他。给他怎么查就行了……要不然太浪费 token 了。」（2026-10-18，会话 `3bf50d7d`）

抄命令进任务书的代价是双份的：写的时候烧一遍 token，子代理读的时候再烧一遍，而抄进去的命令还常常**已经过时**（工具改名、端口变了），子代理照着跑必定出错。

**任务书模板（五段以内，能短则短）**：

```md
# <任务名>
目标：一句话说清要交出什么
做法指路：读 <工作区记忆>，用里面现成的工具/脚本；关键事实见该记忆
约束：只读 / 只改 <目录> / 不许动 <什么>
输出：写到 <路径>，格式 <要求>
验收：<可机器校验的标准>
```

## 三、派出去的活要验收，别信自述

子代理起来之后，主线程只做两件事：**催进度**、**独立复核**。

| 环节 | 做法 |
|---|---|
| 看进度 | 定期看子代理**落盘的文件**判断做到哪一步，不空等交卷 |
| 卡住 | 催办或拆分重派，不要让一个子代理卡死整条线 |
| 验收 | **机器校验**：语法检查、字符串比对、逐条 grep 原文证据；报告里的行号和路径**自己再查一遍** |
| 收尾 | 交付后扫一遍目录，确认没有明文凭据残留 |

子代理说「已完成」不等于做对了。它的报告会过时（行号口径变了、文件被它自己改过），**每一条结论都要对得上原始证据**。

## 四、多个子代理同时写同一个项目：先划互斥范围

并行的前提是**范围和产物互斥**，否则会互相踩。

实测（2026-10-15 浏览器扩展移植）：十几个子代理在同一目录并发工作，构建工具默认往 `build/` 与生成目录里写，几个代理同时构建会互相覆盖。处理办法是**给每个代理指定独立的构建输出目录**，并明确「不要删除共享的生成目录」。

| 冲突点 | 做法 |
|---|---|
| 构建产物目录 | 每个代理用独立输出目录，或约定同一时间只有一个在构建 |
| 同一组文件 | 按目录/模块切分，一个文件只归一个代理 |
| 「发现别人写错顺手改」 | **禁止**。发现越界或错误只回报，由主线程裁定 |
| 收尾 | 主线程统一跑一次全量检查（类型检查 + 构建） |

## 五、反例

```
"把上传优化一下"
```

没有目标（提到多少算成）、没有边界（改哪）、没有验收（怎么算成）、没有禁止（不许动什么）。AI 只能自行发挥，结果必然是要么改少了，要么改多了。

另一种反例：把整张命令清单、账号、端口全抄进任务书 —— 派活时烧一遍 token，子代理再烧一遍读，而且抄进去的多半是旧的。
