# 不擅自修改工作代码

**结论**：在没有证据表明原始代码有问题时，不得修改工作代码。先验证构建 / 运行，再决定要不要改。

## 为什么

2026-08-21 我"认为" Tauri v2 的 invoke 参数格式需要从对象改成数组，擅自改了 4 个文件 21 处调用，导致前端 TypeScript 类型检查失败。原始代码的对象格式本来就是对的 —— 构建验证已经通过了。

## 怎么做

1. 先跑构建 / 类型检查 / 运行，确认是不是真有问题
2. 有报错就贴报错，定位到具体行
3. 凭"觉得这里写法不对"改代码 = 制造问题

## 反例

"这个 API 调用参数格式看起来不对，我改一下" —— 看起来不对不等于不对。
