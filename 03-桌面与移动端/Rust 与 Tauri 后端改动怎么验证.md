# Rust 与 Tauri 后端改动怎么验证

**结论**：四步验证按顺序跑，全绿才打包。另外——**改动涉及平台接口时，桌面和移动两个目标都要验**，漏一端等于隐患没排。

谁需要看这条：改 Tauri 项目的 Rust 后端或原生层的人。

---

## 一、四步验证

按顺序跑，一步不过就停下修：

```bash
cargo fmt --check                              # 格式检查
cargo check                                    # 类型检查
cargo clippy --all-targets -- -D warnings      # 静态检查，警告当错误
cargo test                                     # 跑测试
```

四步全绿才算过。**不要跳步**，也不要只跑最后一步。

---

## 二、两端都要验

**改动涉及平台接口（文件、通知、窗口、权限）时，桌面和移动两个编译目标都要验。**

漏一端 = 隐患未排除 = 不能算验证通过。

（证据：2026-08-16 确立的死纪律）

---

## 三、静态检查只覆盖当前目标

在桌面端跑 clippy，**不会触发移动分支里的代码**。

后果：移动端专属代码写得再烂，桌面端 clippy 也是全绿。

**做法**：平台专属代码要放进对应的条件编译块内取句柄，并且**两个目标分别跑一遍静态检查**。

---

## 四、假错掩盖真错

构建脚本先报错退出时，真正的编译错误被盖住。

典型案例：调用窗口接口需要 `use tauri::Manager`，漏了这个 trait 引用 —— 但看到的报错是构建脚本先炸出来的另一条，修半天修的不是真问题。

**排查顺序**：构建脚本报错先修脚本，修完再看真正的编译错误。

（证据：2026-08-16 提交 6584393）

---

## 五、Windows 特有的环境问题

| 问题 | 现象 | 怎么办 |
|---|---|---|
| SDK 装在非标准路径 | 链接报找不到 `kernel32.lib` | 构建脚本里显式注入 SDK 路径变量 |
| 环境变量在子进程链里拿不到 | 明明设了还是报找不到 | Git Bash 启动的 `node → cmd` 进程链可能不继承用户变量，要在脚本里注入。详见 [Windows 环境变量什么时候生效](Windows%20环境变量什么时候生效.md) |
| 依赖手动开开发者命令提示符 | 换个人跑就扑空 | 脚本里用 `vswhere` 自动定位并注入工具链 |

---

## 六、目录职能分区

**壳层资源（启动图、启动页）放 Rust 工程目录，不放前端的 `public/`。**

放前端的后果：启动遮罩活在网页里，盖不住开机空白，还会跟着前端热更新一起变 —— 但它本该属于软件层，不是网页的一部分。

（证据：项目铁律 4；2026-08-16 提交 8ff05a9）

---

## 七、避坑表

| 坑 | 后果 | 正确做法 |
|---|---|---|
| 只跑最后一步 | 格式和静态问题漏掉 | 四步按顺序全跑 |
| 只验一个平台 | 另一个平台的隐患没排 | 两端都验 |
| 被构建脚本的假错带偏 | 修的不是真问题 | 先修脚本错误 |
| 以为桌面 clippy 全绿就没事 | 移动端代码根本没被检查 | 分目标各跑一遍 |
| 壳层资源放前端目录 | 遮罩不住开机空白、随热更变 | 放 Rust 工程目录 |
| 依赖手动设环境 | 换人换机器就扑空 | 脚本自动探测注入 |
