# Windows 环境变量什么时候生效

**结论**：`setx` 设完**只对之后新开的窗口生效**，当前窗口还是旧值。另外 Git Bash 启动的进程链可能拿不到用户变量，要在脚本里显式注入。

谁需要看这条：在 Windows 上设了环境变量却不生效的人。

---

## 一、`setx` 不是立刻生效

```bash
setx ANDROID_HOME "D:\你的SDK路径"
```

设完之后：

- **当前这个终端窗口**：还是旧值（或者空）
- **之后新开的窗口**：才是新值

所以设完必须**关掉终端重开**。反复重跑 `setx` 没用。

---

## 二、子进程链可能拿不到

已设好的用户/机器变量，在 Git Bash 启动的进程链里（例如 `node → cmd`）**可能读不到**。

**实测案例（2026-08-24）**：用户变量 `WindowsSdkDir` 已经设好，但构建脚本起的 `node → cmd` 子进程里读出来是空的，导致找不到 SDK，Rust 链接报 `kernel32.lib` 缺失。

**修复**：在构建脚本里显式注入：

```js
process.env.WindowsSdkDir = "探测到的SDK路径"
```

（先探测常见安装位置，已存在则不覆盖。）

---

## 三、怎么验证

**不要用 `echo $VAR`** —— Git Bash 里不一定按预期展开，而且就算展开也可能是子进程自己的值。

用 PowerShell 读系统里的实际值：

```powershell
[Environment]::GetEnvironmentVariable("ANDROID_HOME", "User")
```

输出是你设的值就说明设上了。输出为空说明没设上，或者设完没重开窗口。

---

## 四、避坑表

| 坑 | 后果 | 正确做法 |
|---|---|---|
| `setx` 完没重开窗口就验证 | 以为没设上，反复重跑 | 设完关掉终端重开 |
| 以为脚本能读到用户变量 | 子进程里是空的，报错看不出原因 | 脚本里显式注入，别依赖继承 |
| 用 `echo $VAR` 验证 | 结果不可信 | 用 PowerShell 读环境变量 |
| 把路径写死在个人配置里 | 换台机器就失效 | 脚本自动探测，探测失败才回退搜索 |
