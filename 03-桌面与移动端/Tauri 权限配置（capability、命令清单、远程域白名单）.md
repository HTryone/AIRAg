# Tauri 权限配置（capability、命令清单、远程域白名单）

**结论**：壳加载线上页面时，必须在权限配置里把线上域名加进白名单，否则页面调原生命令**直接被拒**，且报错看不出是这个原因。

谁需要看这条：用 Tauri 做壳、壳里加载的不是打包进去的本地产物的人。壳只加载本地产物的可以跳过第三节。

---

## 一、权限是怎么构成的

三层，缺一层就调不通：

```
命令定义（Rust 侧注册）
   ↓
权限清单（构建时自动生成，对应每个命令）
   ↓
capability 配置（声明"谁"可以调"哪些命令"）
```

**任何一层漏了都调不通**，而且报错往往不指向真正漏的那一层。

---

## 二、四个必查项

### 1. 命令清单漏写 → 引用就崩

构建脚本里漏写命令名 → 构建时不生成对应权限 → capability 一引用这个命令就崩。

（证据：2026-08-16 提交 6584393）

### 2. 插件的 `links` 必须写在 `[package]` 段

写进 `[lib]` 段会导致**权限清单不生成**，主工程引用时 panic。

（证据：2026-08-17 提交 6e9eca4）

### 3. 权限声明文件要同步

插件的权限声明 `.toml` 改了，必须同步改 `schema.json`。漏一个就对不上，且报错不直接。

**建议**：在权限声明文件头部写一行注释，注明"改这里必须同步改 schema.json"。

### 4. 早死的构建脚本会掩盖真错误

构建脚本先报错退出时，真正的编译错误（例如缺 `use tauri::Manager`，调用窗口接口需要这个 trait）被盖住，看到的都是假错。

**排查顺序**：构建脚本报错先修脚本，修完再看真正的编译错误。

（证据：2026-08-16 提交 6584393）

---

## 三、远程域白名单（最容易漏的一条）

**场景**：壳加载的是线上页面（前端走热更新，见 [多端同码架构](../12-技术栈架构/多端同码架构（一份前端出%20Web、桌面、移动）.md)）。

这种情况下，页面所在的域名**必须**显式写进 capability 的远程域白名单：

```json
{
  "remote": {
    "urls": ["https://你的前端域名"]
  }
}
```

不写的后果：页面里调原生命令**全部被拒**，而且报错通常只说"权限被拒绝"，不会提示是域名没加白名单。

（证据：项目铁律 3，白名单里写的是前端部署域名）

---

## 四、排查顺序

调不通原生命令时按这个顺序查：

1. 命令有没有在 Rust 侧注册
2. 构建脚本的命令清单里有没有这个命令名
3. 权限清单有没有生成（去生成目录里看）
4. capability 里有没有引用这个命令
5. **如果加载的是线上页面 → 远程域白名单里有没有这个域名**
6. 插件权限声明改了的话，`schema.json` 同步了没有

---

## 五、避坑表

| 坑 | 后果 | 正确做法 |
|---|---|---|
| 线上页面没加远程域白名单 | 原生命令全被拒，报错看不出原因 | 换加载方式时第一件事就是加白名单 |
| 命令清单漏写 | 引用到这个命令直接崩 | 加命令时同步加进清单 |
| `links` 写 `[lib]` 段 | 权限清单不生成、主工程 panic | 写 `[package]` 段 |
| 改权限声明不同步 schema | 两边对不上 | 文件头部写注释提醒 |
| 被构建脚本的假错带偏 | 修半天修的不是真问题 | 先修脚本错误，再看编译错误 |
| 权限相关改动覆盖安装验证 | 覆盖安装不会重新走授权，看到的是假象 | 卸载重装验证 |
