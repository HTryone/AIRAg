# 安卓文件落盘（MediaStore、SAF、文件描述符）

**结论**：一条路走不通就换下一条，四条路线按顺序降级，最后一条任何设备都能用。另外媒体库写入有速度天花板，卡住了就换写入方式，别再调参数。

谁需要看这条：在安卓上写文件（下载、导出、保存）的人。不做安卓可以跳过。

---

## 一、四条路线

```
第一层  媒体库写入（零权限零弹框，现代设备一锤定音）
  ↓ 失败
第二层  直接写文件系统（宽松系统 / 老设备兜底）
  ↓ 失败
第三层  持久目录授权（用户首次选一次文件夹，之后零弹框）
  ↓ 失败
绝对兜底  每个文件弹一次保存框（体验最差，但一定能存）
```

| 路线 | 用户感知 | 适用 |
|---|---|---|
| 第一层 媒体库写入 | 无感知，直接存进下载目录 | 现代设备首选 |
| 第二层 直接写文件系统 | 无感知 | 权限宽松的系统、老设备 |
| 第三层 持久目录授权 | 首次要选一次目录，之后无感知 | 前两层都被限制时 |
| 兜底 逐个文件选择 | 每存一个文件弹一次 | 以上都不行 |

**第一条路线（X3）** 是后来加的第四条，见第三节。它的保存路径与第一层完全相同、同样零弹框，只有写盘方式不同。

---

## 二、四条设计规则

这几条是踩出来的，违反任何一条都会出线上事故。

| 规则 | 说明 | 违反的代价 |
|---|---|---|
| **按用户体感排序，不按好不好实现排序** | 零弹框的排第一，因为它对用户最好 | 把最容易写的放第一，用户每次存文件都要弹框 |
| **降级必须填兜底，不许留空** | 往下降级时必须保证下一级真的能写出东西 | 写入器是空数组还往下走关闭流程 → 崩溃（提交 c8838d8） |
| **最低一层不许删** | 老设备可能只有这一条路 | 删了老设备直接存不了文件 |
| **降级链要能观测** | 记录实际走了哪一层 | 出问题时不知道断在第几层 |

## 三、X3：绕开速度天花板

### 为什么不走第一层

第一层（媒体库写入）实测**写入速度上限约 3.5 MB/s**。

卡点不在代码，在于：内容提供者的事务开销 + 每次写入都要更新媒体索引。加大并发**无效** —— 实测把解密并发从 1 提到 3，写入速度纹丝不动，改动随即回退（提交 0f5fded → c7a17e7）。

判定方法见 [性能问题怎么分层定位](../07-排错方法论/性能问题怎么分层定位.md)：确认是天花板之后就该**换路径，不调参**。

### X3 怎么做

改用**文件描述符 + 通道流式追加写**：

```
打开一次：取得文件描述符 → 建输出流 → 拿通道（通道继承这个描述符）
之后每次：往通道里追加，不重新打开文件
关闭时：关通道和描述符
```

三个要点：

- **打开一次描述符，之后每次追加都不重开** —— 重开一次就要付一次打开开销
- **走普通目录，不走媒体索引** —— 绕开放大开销的根源
- **保存路径与第一层完全相同**（下载目录/应用名，零弹框），用户感知不到换过实现

### X3 的上线方式（值得照抄的部分）

要替换一条正在跑的核心路径，又不敢动老代码：

| 步骤 | 做法 |
|---|---|
| 1. 新路线完全独立 | 新增三个原生命令（打开/追加/关闭）、新增前端写入器和工厂函数，**全是新文件** |
| 2. 老路线一行不改 | 前三层和 HTTP 链路一律不动 |
| 3. 工厂按开关选实现 | 初始化时判断开关，选新工厂还是老工厂 |
| 4. **开关语义用"禁用"** | 设了禁用值才退回老路，**默认走新路线** |
| 5. 新旧体验对齐 | 保存路径、弹框行为完全一致，用户无感知 |

**为什么开关用"禁用"而不是"启用"**：

- 默认走新路线，新代码才真的被跑到、真的被验证。用"启用"语义，新代码会长期没人用，等真切换时才发现是坏的
- 线上出问题，改一个值就退回老路，不用发版、不用改代码
- 新旧对外表现一致，否则差异会污染问题定位

**红线**：新路线只能新增，不得并入现有三层。

（证据：2026-08-22 提交 f40b17c）

## 四、避坑表

| 坑 | 后果 | 正确做法 |
|---|---|---|
| 媒体库里有同名残留记录 | 插入时报"文件已存在"，明明是新文件 | 插入前先查同名记录并删掉（2026-08-20 修复） |
| 写入慢就加并发 | 并发提上去速度纹丝不动 | 先按分层定位确认是不是天花板，是就换写入方式 |
| 目录授权没持久化 | 重启后失效，每次都要用户重选目录 | 拿到授权后必须调持久化接口 |
| 降级路径没填兜底 | 空数组进关闭流程直接崩溃 | 每次降级都要填实际能用的写入器 |
| 删掉最底层那条路 | 老设备直接存不了 | 最低一层保留 |
| 覆盖安装验证 | 看到的可能是旧的壳资源 | 验证原生改动必须卸载重装 |
| 提示文案写死某一种方式 | 走别的路线时提示是错的 | 提示按实际走的路线生成 |
