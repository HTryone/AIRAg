# 出站 25 端口被封怎么办

**结论**：云厂商默认封锁**出站** 25 端口用来防垃圾邮件，自己的邮件服务器发不出去信。改用 465 或 587 端口走第三方中继，不要指望申请解封。

## 为什么

用户环境实测：面板机部署 Poste.io 邮件服务后发信失败，Ak云 HK-02（23.91.96.39）同样封锁出站 25。两者是独立主机，都中招——这不是个例，是云厂商的通用策略。

各家做法：

| 厂商 | 出站 25 |
|---|---|
| 腾讯云 | 默认封，需申请且通常不批 |
| 阿里云 | 默认封，需申请且通常不批 |
| AWS | 默认限流，需提交工单解限 |
| Ak 云 | 默认封 |

注意区分两件事：

| | 方向 | 影响 |
|---|---|---|
| **出站** 25 被封 | 我发出去 | 发信失败 ← 本篇讲这个 |
| **入站** 25 被封 | 别人发给我 | 收信失败，换一台没封的机器做 MX |

## 怎么做

### 第 1 步：确认是不是真被封了

在服务器上执行：

```bash
timeout 10 bash -c 'cat < /dev/null > /dev/tcp/smtp.gmail.com/25' && echo "通" || echo "不通"
```

输出「不通」且服务器本身网络正常 = 出站被封。

`ping` 通不代表 25 通。ICMP 和 TCP 25 是两回事，必须用上面这种连端口的方式测。

### 第 2 步：改走 465 或 587

| 端口 | 加密方式 | 用途 |
|---|---|---|
| 465 | 隐式 SSL/TLS（连上就加密） | 提交邮件 |
| 587 | STARTTLS（先明文再升级） | 提交邮件，**首选** |
| 25 | 无 / STARTTLS | 服务器之间中转，被封的也是它 |

Poste.io 里在发信设置（SMTP relay / smarthost）填第三方服务商的地址和 587 端口，用服务商给的账号密码认证。

### 第 3 步：选一个中继服务

| 类型 | 例子 | 免费额度 | 适合 |
|---|---|---|---|
| 专业邮件推送 | 腾讯云 SES、阿里云邮件推送、SendGrid、Resend | 有免费额度 | 站点通知、注册验证 |
| 用自己的 Gmail / QQ 邮箱 | smtp.gmail.com、smtp.qq.com | 有限额 | 个人低量发信 |
| 换一台不封 25 的机器 | 自建中继 | 无上限但维护成本高 | 量大且不嫌折腾 |

用 Gmail / QQ 邮箱做中继时，密码栏填的是**应用专用密码 / 授权码**，不是登录密码。

### 第 4 步：配好 SPF / DKIM

不配这两个，信能发出去但基本进垃圾箱。

SPF 是域名的一条 TXT 记录，声明哪些 IP 有权用你这个域名发信：

```
v=spf1 include:_spf.example.com ~all
```

加了中继服务后，必须把中继服务商的 SPF 记录也 `include` 进来，否则收件方会判定伪造。

## 反例

- 反复提交工单申请解封 25 —— 多数厂商不批，且批了也随时可能收回。有这时间中继早配好了。
- 只在服务器上配了中继，忘了改域名的 SPF —— 信发出去了但全进垃圾箱，然后以为是中继没生效。
- 用 `ping smtp.qq.com` 测通不通就下结论 —— ping 通跟 25 端口通是两回事。
