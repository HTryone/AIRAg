# 小内存服务器优化

**结论**：内存 1GB 以下的机器，用 zram（内存内压缩交换）撑住，别用磁盘 swap。zram 的压缩算法选 zstd，比默认 lz4 压缩率高。

## 为什么

用户环境实测：Ak云 HK-02（23.91.96.39）内存 899MB，把 zram 的压缩算法从 lz4 升级到 zstd 后可用内存明显改善。

原理对比：

| 方式 | 本质 | 小内存机器上的表现 |
|---|---|---|
| 磁盘 swap | 把内存页写到硬盘 | 内存不够时疯狂读写磁盘，机器卡到 SSH 都连不上 |
| **zram** | 划一块内存当压缩盘用 | 读写都在内存里，只是多一步压缩/解压的 CPU 开销 |

899MB 的机器一旦用到磁盘 swap，基本等于假死——磁盘 IO 会拖垮整个系统，SSH 都敲不动命令。zram 用 CPU 换内存，小内存机器 CPU 通常是闲的，这笔买卖划算。

## 怎么做

### 第 1 步：看现在有没有 swap

```bash
swapon --show
free -h
```

`free -h` 里 Swap 那行全是 0 = 目前没任何交换空间，内存一满直接 OOM 杀进程。

### 第 2 步：装 zram-generator

Ubuntu 22.04+ / Debian 12+ / Rocky 9+：

```bash
apt install -y systemd-zram-generator
```

CentOS 系用 `yum install -y systemd-zram-generator`。

装完先**别重启**，做第 3 步配好再启。

### 第 3 步：写配置

```bash
cat > /etc/systemd/zram-generator.conf <<'EOF'
[zram0]
zram-size = min(ram / 2, 4096)
compression-algorithm = zstd
EOF
```

| 参数 | 含义 |
|---|---|
| `zram-size` | zram 设备大小。`ram / 2` = 物理内存的一半；`min(..., 4096)` 封顶 4GB |
| `compression-algorithm` | 压缩算法，`zstd` 压缩率高于 `lz4` |

899MB 的机器配出来约 450MB 的 zram，实际能装下 1.5 倍左右的数据（看压缩率）。

### 小内存机：zram-size 用固定值，不写 ram / 2 或 PERCENT

内存 < 1GB 的机器，别用 `ram / 2` 这种按比例算的大小，也别用 legacy `zramswap` 的 `PERCENT` 写法——比例换算出来偏小且不稳，重启后可能没按预期生效。直接写固定 MB：

```bash
cat > /etc/systemd/zram-generator.conf <<'EOF'
[zram0]
zram-size = 500
compression-algorithm = zstd
EOF
```

| 参数 | 含义 |
|---|---|
| `zram-size = 500` | 固定 500MB，不随内存比例浮动 |

证据：一台 899MB 内存的机器，zram 实测压缩比约 7×（148.8MB 原始数据压到 19.8MB），固定 500MB 的 zram 实际能装下数倍于物理内存的数据，比 `ram / 2 ≈ 450MB` 更稳，且不受比例换算抖动影响。

> 若用 legacy 的 `zramswap`（`/etc/default/zramswap`），对应写 `SIZE=500` 并**注释掉** `PERCENT` 那行，效果一样。

### 第 4 步：调整内核倾向

```bash
cat > /etc/sysctl.d/99-zram.conf <<'EOF'
vm.swappiness = 100
vm.vfs_cache_pressure = 50
EOF
sysctl --system
```

| 参数 | 作用 |
|---|---|
| `vm.swappiness` | 系统多积极地把内存页换出去。默认 60，配 zram 后调到 **100** —— zram 在内存里，换出去代价很小，应该积极用 |
| `vm.vfs_cache_pressure` | 回收目录/文件缓存的倾向。调低到 50，让系统更愿意留住缓存 |

`swappiness` 这个方向容易搞反：配磁盘 swap 时要**调低**（少用慢速磁盘），配 zram 时要**调高**（多用快速压缩内存）。

### 第 5 步：启用并验证

```bash
systemctl daemon-reload
systemctl start systemd-zram-setup@zram0
swapon --show
```

看到 `NAME` 列是 `/dev/zram0`、`TYPE` 列是 `partition` = 生效了。

再确认压缩算法确实生效：

```bash
cat /sys/block/zram0/comp_algorithm
```

输出里 `zstd` 外面带方括号（如 `lz4 lzo [zstd]`）= 当前用的就是它。

### 第 6 步（可选）：限制连接跟踪表

小内存机器上 conntrack 表过大也是内存杀手。899MB 的机器建议压到 16384：

```bash
echo "net.netfilter.nf_conntrack_max = 16384" >> /etc/sysctl.d/99-zram.conf
sysctl --system
```

用户环境实测：Ak云 HK-02 把 conntrack 和 zram 一起调过。

## 排查内存还是不够

先看是谁在吃内存：

```bash
ps aux --sort=-%mem | head -10
```

再看系统日志有没有 OOM 杀进程的记录：

```bash
journalctl -k | grep -i "out of memory"
dmesg | grep -i "killed process"
```

看到 `Killed process 1234 (xxx)` = 已经触发 OOM killer，说明内存是真不够，zram 也救不回来，得杀服务或升配。

## 反例

- 给 899MB 的机器配 4GB 磁盘 swap —— 一用就假死，SSH 敲命令都卡。
- zram 配完不改 `swappiness`，还留着默认的 60 —— zram 没被充分利用，等于白配一半。
- 只看 `free -h` 里 swap 总量变大了就以为好了 —— 没确认 `comp_algorithm` 是 zstd，实际跑的就是默认的 lz4。
