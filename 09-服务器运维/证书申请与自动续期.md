# 证书申请与自动续期

用 acme.sh 申请 Let's Encrypt 免费证书，并让它自己续。这篇是从零到自动续期的完整流程。

用户环境实测：面板机用 acme.sh 给 `home.315461.xyz`、`jp2.315461.xyz` 申请了 Let's Encrypt 证书。

---

## 一、这是什么

| 词 | 指什么 |
|---|---|
| Let's Encrypt | 免费证书颁发机构（CA），证书 **90 天**过期 |
| acme.sh | 纯 shell 写的 ACME 协议客户端，不依赖 Python，装完自己带续期定时任务 |
| 泛域名证书 | `*.example.com` 一张证书覆盖所有子域名，**必须用 DNS 验证**才能申请 |

90 天这个点是关键：手动续根本记不住，必须自动化。

---

## 二、两种验证方式怎么选

| 方式 | 原理 | 能申请泛域名吗 | 什么时候用 |
|---|---|---|---|
| **HTTP 验证** | 在网站目录放个临时文件，CA 来访问验证 | 不能 | 单域名，且 80 端口对外开放 |
| **DNS 验证** | 在域名解析里加一条 TXT 记录 | **能** | 要泛域名，或 80 端口不通 |

**要泛域名就用 DNS 验证，没有别的选择。**

---

## 三、从零做（HTTP 验证，单域名）

### 第 1 步：安装

```bash
curl https://get.acme.sh | sh -s email=htryone@163.com
source ~/.bashrc
acme.sh --version
```

装完自动写入一条 cron 定时任务，每天检查一次该续的证书。

### 第 2 步：申请

```bash
acme.sh --issue -d home.315461.xyz -w /var/www/html
```

| 参数 | 含义 |
|---|---|
| `-d` | 域名。多个域名就写多个 `-d` |
| `-w` | 网站根目录，CA 会来 `http://域名/.well-known/acme-challenge/` 取文件 |

要求：域名已解析到这台服务器，且 **80 端口能被公网访问**。

一张证书覆盖多个域名：

```bash
acme.sh --issue -d home.315461.xyz -d jp2.315461.xyz -w /var/www/html
```

第一个 `-d` 是主域名，后面是附加的。

### 第 3 步：装到 Web 服务器

**不要直接把证书路径指到 `~/.acme.sh/` 下面**——那属于 acme.sh 的内部目录，结构可能变。用 `--install-cert` 复制到业务目录：

```bash
mkdir -p /etc/nginx/ssl/home.315461.xyz

acme.sh --install-cert -d home.315461.xyz \
  --key-file       /etc/nginx/ssl/home.315461.xyz/key.pem \
  --fullchain-file /etc/nginx/ssl/home.315461.xyz/cert.pem \
  --reloadcmd      "systemctl reload nginx"
```

| 参数 | 含义 |
|---|---|
| `--key-file` | 私钥放哪 |
| `--fullchain-file` | 完整证书链放哪（**用 fullchain，不是 cert**） |
| `--reloadcmd` | 证书更新完执行的命令，用来重载 Web 服务器 |

`--reloadcmd` 是关键：续期脚本只负责换新证书文件，不会主动通知 nginx。不配这个，证书文件更新了但 nginx 还在用内存里的旧证书，照样过期。

## 四、泛域名（DNS 验证）

需要先去域名服务商拿 API 密钥（能程序化改解析的那种）。以腾讯云 DNSPod 为例：

```bash
export DP_Id="你的ID"
export DP_Key="你的Token"

acme.sh --issue --dns dns_dp -d 315461.xyz -d '*.315461.xyz'
```

这两行 `export` **不能省**。acme.sh 只从环境变量里读 DNS 服务商的密钥，命令行没有对应的参数可以填。这不是为了少打字而引入的变量，是工具要求的传参方式。

设一次之后 acme.sh 会把密钥存下来，续期时自动复用。换个终端窗口要重新设，或者用下面的方式一次设好。

不同服务商的插件名不同，`dns_dp` 是 DNSPod，阿里云是 `dns_ali`，Cloudflare 是 `dns_cf`。完整列表见 acme.sh 官方 wiki 的 dnsapi 目录。

## 五、日常管理

```bash
acme.sh --list                          # 看所有证书和剩余天数
acme.sh --renew -d home.315461.xyz --force   # 手动强制续一张
acme.sh --remove -d home.315461.xyz     # 删掉不用的
acme.sh --upgrade                       # 升级 acme.sh 自己
crontab -l | grep acme                  # 确认续期定时任务在
```

## 六、排查

### 申请报 `Invalid response` / `Fetching` 失败

CA 访问不到验证文件。按顺序查：

1. 域名解析到这台机器了吗：`dig home.315461.xyz +short`
2. 80 端口通吗：本机 `curl -I http://home.315461.xyz/`，服务器外也要通
3. nginx 有没有真指向 `-w` 那个目录：`nginx -T | grep root`
4. 目录权限：acme.sh 得能写

### 想看详细过程

```bash
acme.sh --issue -d home.315461.xyz -w /var/www/html --debug 2
```

### 证书到期了但没自动续

按顺序查：

```bash
crontab -l | grep acme
systemctl status cron
acme.sh --list
```

`cron` 服务停了是常见原因，定时任务写了也不会跑。

### 验证线上证书

```bash
echo | openssl s_client -connect home.315461.xyz:443 -servername home.315461.xyz 2>/dev/null | openssl x509 -noout -dates
```

看 `notAfter` 那行。

### 续期成功但线上还是旧证书

现象：`acme.sh --list` 显示已续期，但浏览器或 `openssl s_client` 查线上证书，`notAfter` 还是旧日期。

原因：`--reloadcmd` 没配或没生效，证书文件更新了，但 Web 服务器还在用内存里加载的旧证书。

排查：
```bash
nginx -T | grep ssl_certificate          # 看 nginx 实际引用的证书文件路径
echo | openssl s_client -connect 域名:443 -servername 域名 2>/dev/null | openssl x509 -noout -dates   # 看线上实际有效期
ls -l <证书目录>/cert.pem                # 对比文件修改时间，确认文件确实更新了
```

修复：手动重载 Web 服务器让新证书生效，并确认当初 `--install-cert` 配了 `--reloadcmd`：
```bash
systemctl reload nginx
```

实测：某面板曾因 reload 缺失，续期后站点仍用旧证书，补上 reload 并手动重载后验证通过。

## 七、常见坑

| 坑 | 后果 | 正确做法 |
|---|---|---|
| nginx 里配的是 `cert.pem` 不是 `fullchain.cer` | 部分浏览器报证书链不完整 | 一律用 `--fullchain-file` |
| 直接引用 `~/.acme.sh/域名/` 下的文件 | acme.sh 目录结构一变就全崩 | 用 `--install-cert` 复制到业务目录 |
| 忘了配 `--reloadcmd` | 文件更新了，nginx 还在用旧证书 | 必配重载命令 |
| 想用 HTTP 验证申请泛域名 | 必然失败 | 泛域名只能 DNS 验证 |
| 证书 90 天过期当小事 | 到期当天站点全红 | 装完就跑 `acme.sh --list` 确认定时任务在 |
| Let's Encrypt 有频率限制 | 反复失败重试会被限流几小时 | 调通前加 `--staging` 用测试环境试 |

调试阶段加 `--staging`，用测试 CA 跑通流程再换正式，避免触发限流。
