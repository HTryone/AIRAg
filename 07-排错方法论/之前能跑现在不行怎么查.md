# 「之前能跑现在不行」怎么查

**结论**：先确认"之前"到底是什么状态，用 git diff 找出中间改了什么，不要重新从头排查。

## 为什么

用户说"之前还正常的，现在怎么运行不了了" —— 这句话本身就是最强线索：改动引入的回归，不是环境问题。

## 怎么做

1. 问清"之前"是哪一版（时间点、提交号、还是某个文档版本）
2. 对比差异

   ```bash
   git diff <好版本>..HEAD -- <相关文件>
   git log --oneline -20
   ```

3. 找到差异点后，逐个回退验证

## 常见引入回归的"优化"

| 自以为的改进 | 实际后果 |
|---|---|
| 把长路径改成变量 | 变量换窗口失效 |
| 把重复内容合并成一处 | 遗漏某个引用点 |
| 为了简洁删掉"冗余"配置 | 删掉了必需项 |
| 重写文件而不是定点改 | 丢掉没注意到的细节 |

**文档 / 脚本回归**往往比代码回归更难发现，因为没有编译器和测试兜底。改完必须实际跑一遍。
